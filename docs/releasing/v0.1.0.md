# OXC for TSRX 0.1.0

> Draft release notes for the reviewed 0.1.0 candidate. Do not describe these
> artifacts as published until the registry, Marketplace, site, and social
> approvals in the launch runbook have each been granted and verified.

OXC for TSRX brings native parsing, Oxlint, Oxfmt, and editor tooling to
`.tsrx` through one public `oxc-tsrx` package. Each release
pins a qualified official OXC revision; future revisions are adopted
deliberately behind one narrow Rust adapter. It is a community toolchain
integration, not a fork, and the npm, Vite+, and editor layers stay thin.

## Included

- `oxc-tsrx`, the single public install with parser, lint, format, custom
  JavaScript plugin-development, compatibility, and language-server surfaces;
- exact parser, runtime, lint, and format implementation dependencies hidden
  behind that public boundary;
- explicit, reversible project-local compatibility facades for current Vite+
  lint and format package resolution;
- type-aware linting as an explicit `oxlint-tsgolint` opt-in;
- integration with the released official OXC extension: canonical ordinary
  diagnostics plus dynamically registered native TSRX diagnostics, formatting,
  and validated fixes, without another required extension;
- an optional legacy VS Code client for TSRX-only automatic activation; and
- release manifests and hosted build lanes for eight 64-bit native npm targets
  and eight matching platform VSIX artifacts.

Diagnostics and fixes use authored TSRX byte spans. Formatting is accepted only
after the result rescans and preserves the structural fingerprint before write.
Separately, the release gates reparse and prove one-pass convergence across the
179-file parser-valid Markless corpus in a disposable copy without writing to
Markless.

## Performance contract

The release does not turn the TSRX hot path into JavaScript AST materialization.
The aggregate-selected same-machine evidence reports 220.44 MiB/s for native
scan/projection/parse, 114.31 MiB/s sequential formatting, 770.19 MiB/s batch
format-check, 3.96 ms cold lint p95, and 2.83 ms fresh editor
open-to-diagnostics p95.
These are dated measurements with frozen budgets, not universal machine-speed
promises. The exact raw reports are
[lint](../../benchmarks/native-lint/results-1789790934847.json),
[format](../../benchmarks/native-format/results-1789790938649.json),
[type-aware](../../benchmarks/type-aware/results-1789790940149.json),
[Vite/Vite+](../../benchmarks/vite/results-1789790952481.json),
[editor](../../benchmarks/editor/results-1789790953137.json), and the

the generated

## Known boundaries

- Current Vite+ releases still resolve literal `oxlint` and `oxfmt` package
  names. `npx oxc-tsrx setup` creates only those qualified reversible facades
  and must be rerun after a clean install until shared provider discovery
  ships.
- The current official OXC extension can accept dynamic `.tsrx` capabilities
  but does not activate from opening a `.tsrx` file alone. A TSRX-only
  workspace must open JS, TS, or JSON once; the optional legacy client remains
  only for automatic activation until upstream closes that event gap.
- Embedded `<style>` payload bytes are preserved but not formatted or
  validated. Enabling OXC CSS formatting at the pinned revision would violate
  the no-patch dependency contract.
- Type-aware rules launch the supported TypeScript-Go companion only when
  explicitly requested; the default syntax lane remains one native OXC parse.
- The public playground is a static preview. Interactive native execution is
  restricted to the localhost development server and is not deployed.
- Platform intent is the eight-target matrix in the launch manifest and hosted
  workflow. The host package and VSIX are built and executed locally; producing
  and validating all eight release candidates remains a required post-push
  hosted gate. No JavaScript or WebAssembly fallback silently replaces a
  missing native build.
